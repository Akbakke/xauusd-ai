## Population and reproducibility

The recipe binds batch size 16, 313,399 TRAIN rows, up to 30 epochs, patience 5, and deterministic FP32. An epoch has 19,588 optimizer updates, including the final seven-row minibatch. Cosine scheduling advances once after the final TRAIN checkpoint, before the validation-phase checkpoint (`trainer:12624–12638`). A crash on either side of that transition restores the appropriate scheduler state rather than advancing it twice.

Full-population means **all Entry pairs once per epoch**, with **four sampled Exit transitions per Entry**, both sides at every sampled state, plus one state-zero anchor used for Entry targets. That is 1,253,596 sampled transitions per full epoch; it does not mean enumerating all possible Exit states. Runner `:254–280` verifies the entire parent population and chooses the established 65,536-transition sampler-chunk geometry, then expands the stream to a full population.

`gx1/contracts/unified_exit_random_access_sampler_v1.py:284–359` wraps a population-length interval of the deterministic stream, checks unique complete Entry coverage, and records the schedule hash. Trainer `:12118–12154` converts child order to dataset parent coordinates; dataset `:5184–5195` maps them back when emitting Exit indices. This avoids pairing one Entry token with another Entry's Exit episode. Because the Entry affine stream is fixed and the epoch spans one full population, Entry order repeats across full epochs; transition choices advance. That behavior is explicit in the stream-preservation design, not evidence of skipped rows.

An apparent duplicated importance-weight multiplication at random-access training `:402–405` has **no active numerical effect**: sampler `:453` requires weight exactly `1.0`, and collator `:255` requires the view's loss weight to equal it. It would require correction if nonunit weights were introduced, which is outside this frozen recipe.

Saved state contains raw model, target model, AdamW, EMA, scheduler, Python/NumPy/CPU/CUDA RNG, exact epoch order, batch cursor, task flags, and selection progress (`trainer:12516–12540`). Restore loads these before training (`:11083–11169`), rebuilds/checks the deterministic native order (`:12420–12426`), and uses a separate DataLoader generator so iterator construction does not consume the restored model RNG (`:12661–12664`). Deterministic mode disables TF32 and cuDNN benchmarking and requests deterministic algorithms (`:3324–3387`). This supports same-state resumption on the frozen stack; it is not an independently executed bitwise GPU-resume test.

The alternating checkpoint writer writes/fsyncs the inactive state slot before publishing the atomic pointer (`:2124–2156`); load verifies the pointer digest and payload cursor (`:2045–2069`). No partial gradients are saved because the sole configured accumulation width is one.

## Gate saturation: confirmed seed risk, recovery not structurally blocked

The existing V34 result at `/home/andre2/GX1_RUNS/UNIFIED_EXIT_RANDOM_ACCESS_V21_ADCE4082_BOOT363/FULL_VAL_CPU_V34/rollout/VAL_RESULT.json` records:

- Entry feature gates: 31,343 upper-saturated elements among 3,877,632 observations, or 0.8083%; range approximately `8.57e-23` to `2.0`.
- Exit feature gates: zero saturated elements among 3,102,965,360 observations; range `0.450105–1.480214`.

The gate is `2*sigmoid(Linear(context))`, initialized neutral; there is no clamp, detach, or explicit freeze (`gx1/models/entry_v10/entry_v10_ctx_hybrid_transformer.py:1284–1293,2085–2089`). At an exactly rounded sigmoid output of one, the ordinary local sigmoid derivative is zero. Therefore those saturated Entry examples do not themselves train that gate's logits through that route.

However, the **same gate parameters** are also used for Exit, with the Exit local state as context (`:2641–2644`). The measured seed Exit route is nonsaturated and can supply gradients. Other Entry contexts and changes to upstream representations can also move the logits. Aggregate all-task gradient flags do not prove recovery of individual gate coordinates, but saturation of the seed's Entry observations also does not prove permanently dead parameters.

Weight decay alone cannot be treated as an effective recovery mechanism: `lr*weight_decay=1e-8`, so even ideal constant-LR real arithmetic shrinks a parameter by less than 0.6% over 30 full epochs; cosine shrinks less, and FP32 can round such a factor to one. Recovery depends on actual gradients and evolving representations. No current full-TRAIN coordinate-level evidence was loaded. V34 stores aggregate extrema/counts, so it cannot identify a coordinate that is saturated for every input.

The selection health rule rejects any observed feature gate at either exact bound (`trainer:5444–5455`). A future candidate that retains saturation will fail that rule even with profitable Bps. **This is a conditional future admission risk, not proof that the active training cannot recover.** Smallest action now: preserve the running model and use the already scheduled first full candidate VAL to determine whether saturation persists; no speculative reset or gate rewrite is justified by this evidence alone.

## Limited defects and gaps

1. **Conditional low-severity resume-tail evidence defect.** `train_epoch` resets its HOLD/EXIT target-greedy counts per invocation (`trainer:8950` onward), while the final guard requires both types to appear (`:9405–9415`). After resuming near an epoch boundary, this is a check of the remaining fragment, not the full epoch. A valid full epoch can therefore be rejected if its final fragment contains only one type. The final optimizer checkpoint occurs before this guard (`:9271–9274`), so a subsequent resume from that checkpoint enters VAL directly (`:12624`), making this particular check interruption-dependent. No such failure was observed in the main run. If it occurs, the smallest correction is to base the guard on persisted full-epoch evidence or explicitly scope it to a complete in-process epoch; do not rerun the trained population solely to reconstruct statistics.

2. **Training diagnostics are not complete epoch evidence.** The resumable coordinator discards `train_epoch`'s return value (`trainer:12679–12716`), and the durable progress envelope has task-weight gradient flags but no full TRAIN loss/gate accumulators (`:1244–1284`). Those flags inspect gradients of the task log-variance parameters (`:431–447`), not every prediction head or gate coordinate. Thus a live pointer plus all task flags cannot independently establish that every feature gate is adapting or provide full-epoch TRAIN loss trends. This limits conclusions from the available telemetry; it does not change the gradient objective or invalidate the scheduled full VAL result. No extra training/report run is recommended.
